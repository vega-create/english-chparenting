## 表：`ae_events`（學習行為事件）

每一次作答、重聽、進出課程都是一列。

| 欄位 | 型別 | 意思 | 分析時要注意 |
|---|---|---|---|
| `id` | bigserial | 流水號 | 不代表時間順序以外的意義 |
| `device_id` | text | 隨機 UUID，代表「這台裝置」 | **清瀏覽器資料會換一組**。同一個孩子換裝置＝兩組，只有登入才接得起來 |
| `user_id` | uuid | 帳號代號，沒登入是 null | 跨裝置縱貫追蹤唯一的依據。可 join `auth.users` ⇒ 這是**去識別化**不是匿名 |
| `ts` | timestamptz | 事件時間（到秒以下） | 時區是 UTC，畫圖前先轉 +08 |
| `kind` | text | 事件類型，見下表 | |
| `level` | int | 第幾級 1–12 | 前後測事件是 null |
| `mission` | int | 第幾課 1–20 | |
| `step` | text | 學習步驟 | `wakeup`/`discover`/`challenge`/`talktime`/`complete`/`placement` |
| `item` | text | 題目 ID 或單字 | 作答題是 `q3:apple`（第幾題＋答案），重聽是單字或 `d2`/`s1` |
| `correct` | boolean | 答對與否 | 只有 `answer`/`speak`/前後測有值 |
| `attempt` | int | 第幾次嘗試 | 熱身題固定 1（不給重答）；口說可多次 |
| `score` | numeric | 分數 | 口說是 0–1 相似度；破關是星數；前後測是答對題數 |
| `ms` | int | 耗時（毫秒） | **最有價值的欄位**。作答題＝從出題到按下答案；`session`＝該步驟停留；`abandon`＝整課到放棄為止 |
| `audio_src` | text | 音檔來源 | `el`=ElevenLabs 合成、`human`=真人、`tts`=瀏覽器內建（音質最差） |
| `app_version` | text | 介面版本 | 見 `src/lib/version.ts`。**改版前後的資料一定要用這個切開** |
| `bucket` | text | A/B 分組 `A`/`B` | 由 device_id 雜湊，同裝置永遠同組。**目前只記錄，還沒有任何功能依它改變行為** |
| `meta` | jsonb | 其他 | `type`=題型、`chose`=孩子選了什麼、`total`=測驗題數 |

### `kind` 一覽

| kind | 何時寫入 | 有值的欄位 |
|---|---|---|
| `lesson_start` | 進入課程封面 | level, mission |
| `lesson_end` | 走到破關畫面 | level, mission, score(星數), ms, meta.percent |
| `session` | 離開任一步驟 | level, mission, step, ms |
| `abandon` | 關頁時還沒破關 | level, mission, step(停在哪一步), ms |
| `answer` | 每次作答 | level, step, item, correct, ms, attempt, meta.type/chose |
| `replay` | 重聽音檔 | level, mission, step, item, audio_src |
| `speak` | 口說評分 | item(目標句), score 0–1, attempt, correct |
| `pretest` | 起點測驗 | step=`placement`, score, ms（總結一列）＋每題各一列(item, correct, ms) |
| `posttest` | 複測 | 同上 |

⚠️ **前後測各會寫入 1 + 10 = 11 列**：一列總結（有 score、沒有 item），
十列逐題（有 item、沒有 score）。算平均分時記得 `where item is null`，
不然會把逐題列也算進去。

## 表：`ae_progress`（學習進度＋同意紀錄）

| 欄位 | 意思 |
|---|---|
| `user_id` | 帳號代號（主鍵） |
| `data` | 進度 JSON（完成哪幾課、星數、連續天數） |
| `research_consent` | 家長是否同意研究用途，預設 false |
| `consent_at` | 同意的時間戳，**IRB 送審時證明有取得同意** |

---

## View

| View | 用途 |
|---|---|
| `ae_daily_summary` | 每日活躍裝置、完成課數、答對答錯數、平均每課秒數 |
| `ae_prepost` | 每個受試者的前測／後測分數與時間，直接拿去跑配對 t 檢定 |
| `ae_dropoff` | 哪一級／哪一課／哪一步被放棄最多次 |

三個 view 都要用 **service key** 讀（anon key 讀不到別人的資料）。

---

## 三個最容易弄錯的地方

1. **`device_id` 不等於一個人。** 清瀏覽器、換裝置都會產生新的。
   要算「幾個孩子」請用 `coalesce(user_id::text, device_id)`，並在論文裡
   說明未登入者可能重複計數。

2. **`app_version` 沒切開就不能比。** 改版會改變孩子的體驗，
   把 1.0 和 1.1 的資料混在一起算平均，等於把兩個不同的實驗條件加起來。

3. **同意是分水嶺。** `hasConsent()` 為 false 時 `track()` 直接 return，
   一列都不會寫。所以資料量少不代表沒人用，可能只是沒人開同意。
   要估真實使用量請看 GA4，不要看 `ae_events`。
