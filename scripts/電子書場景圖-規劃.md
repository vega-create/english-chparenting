# 電子書內頁場景圖規劃（2026-08-10）

## 現況：內頁的視覺是系統 emoji

每課 4 頁故事，全站 **968 頁**。每頁的視覺組成：

```
大 emoji（scene.image）        ← 例如 👀，就是系統字體的 emoji
+ 3 個小 emoji 動畫（sceneEmojis）
+ 角色去背圖（Coco 拍手）      ← 這個很精緻
+ 該級固定底圖 + 米色面板
```

**問題**：那顆大 emoji 跟旁邊的角色去背圖、底圖擺在一起質感落差明顯。
跟「電子音混在真人錄音裡」是同一類問題 —— 單看不難看，並排就露餡。

## 建議：只做前 50 種裡「還沒有圖」的那些

前 50 種扣掉上面 34 個可複用的，實際要生的大約 **25–30 張**，
就能把 **62% 的頁面**從系統 emoji 換成跟角色同一個風格的插圖。

風格沿用 [單字圖生成指令.md](../單字圖生成指令.md)（可愛卡通、厚描邊、光澤、純白底去背），
四合一 2×2 一次生 4 個 → **只要 7–8 張生成**。

## 實作方式（程式端）

跟單字圖同一套 fallback 機制：

```tsx
// 有場景圖就用圖，沒有就退回 emoji —— 不會破版
<SceneImage emoji={scene.image} />
```

檔名用 emoji 的 codepoint，例如 🎉 → `public/scenes/1f389.png`。
沒有對應檔案時自動顯示原本的 emoji，所以**做幾張就換幾張，不用一次做完**。

---

## 不建議做的

- **每頁一張專屬插圖（968 張）** —— 是封面工程量的 4 倍，而且每張只用一次
- **sceneEmojis 那 3 個小圖** —— 它們是彈跳動畫，小尺寸看不出質感差異，emoji 反而輕巧
- **只出現 1 次的 125 種** —— 做了只影響一頁
