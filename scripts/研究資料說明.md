# 學習行為資料收集（給日後論文用）

2026-08-08 建置。Vega 準備報考台中教育大學數位內容科技研究所，
提早開始累積縱貫資料，考上後可直接進入分析階段。

## 定位（同意書上的說法）

不寫「碩士論文」，因為還沒考上。對外的說法是：
**冒險英語同時是一個研究場域，資料可能整理成研究成果對外發表。**
這個說法現在就成立，之後考上了也不用改口。

### 為什麼要現在就把同意做好

期刊／研討會投稿多半要求倫理審查（IRB）。沒有校方身分現在申請不了，
但關鍵在於：**已經收集好的匿名資料，日後申請多半走「免除審查」**
（exempt review，理由是無法辨識個人＋非前瞻性介入），
比考上之後才開始前瞻性收集要簡單很多。

所以現在這個設計是刻意的：
1. 完全不存個資（隨機 device_id，語音只存分數不存內容）→ 符合免除審查條件
2. `consent_at` 存同意時間戳 → 送審時證明取得同意
3. 預設關閉、隨時可撤回 → 符合自願參與原則

⚠️ 真正送審前還是要問一次該校 IRB 認不認回溯資料，各校認定不同。

### 「匿名」還是「去識別化」——這個要講清楚

沒登入 → `device_id` 是隨機 UUID，**真的匿名**，回頭也對不出是誰。

有登入 → `user_id` 是 Supabase 的帳號 UUID，而 `auth.users` 裡有 email。
兩張表 join 得起來 ⇒ 這叫**去識別化／假名化（pseudonymized）**，不是匿名。

所以同意書改成講「帳號代號（一串亂碼，不是 email）」，不再宣稱「無法對應到任何一個人」。
IRB 很在意這個區分，先講清楚比事後被抓包好。

為什麼不乾脆丟掉 `user_id`：跨裝置的縱貫追蹤是這批資料最值錢的部分
（同一個孩子換手機還接得起來），砍掉會讓存活分析、配對 t 檢定都不能做。
留著＋說法誠實，比砍掉划算。

## GA4 / BigQuery

GA4 跟 `ae_events` 分工，不互相取代：

| | 用途 | 要不要接 BigQuery |
|---|---|---|
| GA4 | 流量、來源、有多少人、留存概況 | 想看 event-level 才需要 |
| `ae_events` | 每個單字答對答錯、重聽次數、口說分數 | 不需要，直接查 Supabase |

**BigQuery 匯出**：GA4 免費版就能開每日匯出（Admin → BigQuery links）。
以本站流量規模，BigQuery 每月 10 GB 儲存 + 1 TB 查詢的免費額度綽綽有餘。
只有 streaming export 才要錢，選 daily 就好。

**能送什麼進 GA4**：
- ✅ `user_id` = Supabase 帳號 UUID（假名，合規）
- ❌ email、姓名 — **違反 GA 服務條款**，被抓到會停帳號，連 learn 那邊一起沒了
- GA4 用 IP 判地區之後就丟掉，BigQuery 匯出裡沒有 IP，只有城市層級

**兒童網站必關的兩個開關**：Google 信號（Google Signals，人口統計/再行銷）、
廣告個人化。開了會跟 `requestNonPersonalizedAds = 1` 打架。

**像素（Meta Pixel 等）**：只放家長端頁面（首頁介紹、家長中心、部落格），
不要放進課程流程 — 跟廣告用同一套切法。

## 可做的分析

### 1. 學習曲線（最容易，圖最漂亮）
同一個單字在課程中重複出現，取 `answer` 事件依 `item` 分組，
看第 1/2/3 次遇到的正確率。上升曲線即為學習效果證據。

```sql
select item,
       row_number() over (partition by device_id, item order by ts) as nth,
       avg(case when correct then 1.0 else 0 end) as acc
from ae_events where kind = 'answer'
group by item, nth order by nth;
```

### 2. 流失分析 / 存活曲線
橫軸課數、縱軸仍在使用的比例，找出難度斷層。

```sql
select level, mission, count(distinct device_id) as reached
from ae_events where kind = 'lesson_start'
group by level, mission order by level, mission;
```

### 3. 遊戲化元素的預測力（邏輯迴歸）
自變項：連續天數、累積星數、徽章數
依變項：30 天後是否仍在使用
→ 匯出成 CSV 丟 SPSS / R 跑。

### 4. 重聽次數與正確率的相關（Pearson r）
每個 device 的 `replay` 次數 vs 該課 `answer` 正確率。

### 5. 口說進步（配對 t 檢定）
同一句 `speak` 事件的 `score`，比較第一次與最後一次。

### 6. 組內前後測（配對 t 檢定）——門檻最低的因果證據
`ae_prepost` view 直接給你每個受試者的前後測分數。

```sql
select subject, pre_score, post_score, post_score - pre_score as gain
from public.ae_prepost where post_score is not null;
```

前測 10 題固定題目，後測用一模一樣的題目（上滿 20 課後才開放），
所以配得起來。測驗刻意不給對錯回饋，避免後測時孩子記得答案。

### 7. A/B 測試（真正的因果推論）
`bucket` 欄位已經在寫了（device_id 雜湊分 A/B，同裝置永遠同組），
但**目前沒有任何功能依分組改變行為**——也就是說現在兩組是一樣的。

要開始跑實驗時，用 `variantOf()` 切介面即可，歷史資料的分組欄位是連續的：

```ts
const showFanfare = variantOf('fanfare', { A: false, B: true });
```

⚠️ **倫理提醒**：觀察性資料（現在在收的）事後補 IRB 相對容易；
但 A/B 是**介入性研究**，多數 IRB 要求事前核准，事後補很難過。
所以「分組欄位先留著」跟「真的開始跑實驗」是兩件事，
後者建議等有校方身分、送過 IRB 再啟動。

### 8. 中途離開分析
```sql
select * from public.ae_dropoff limit 20;
```
哪一課、哪一步被放棄最多次。這是最直接可以拿去改產品的分析。

### 9. 音檔來源的影響
`audio_src` 記了每次播放是 ElevenLabs 合成還是瀏覽器 TTS。
目前 fallback 到 tts 的多半是缺檔案，可以先當「音質不佳」的自然實驗來看。
要做正式的「合成 vs 真人」比較，得先錄一批真人版，見 [音檔來源紀錄.md](音檔來源紀錄.md)。

## 收得到資料的前提：登入 → 同意

`track()` 第一行就是 `if (!hasConsent()) return;`，所以**沒同意就一筆都不寫**。
而同意只在兩個地方問得到：

1. 登入後跳出的 `ConsentGate`（家長才會走到登入這步，那時候問才算有效同意）
2. 家長中心的開關

登入是選配的，課程不登入就全部能玩。所以**引導登入 = 同意的主要漏斗**。

### 登入對研究的價值

| | 不登入 | 登入 |
|---|---|---|
| 清瀏覽器資料 | `device_id` 換一組，同一個孩子被算成新的人 | 接得回來 |
| 換手機／平板 | 算兩個不同的人 | 同一個人 |
| 前後測配對 | 中間清過快取就配不起來 | 穩 |
| 家長要求刪除 | 技術上做不到 | 做得到 |

`device_id` 被清掉是縱貫研究最大的敵人——同一個孩子被算成三個人，
留存率、學習曲線、存活分析全部失真。

### 引導登入放在哪

- **破關畫面**（`LoginNudge`）：剛拿到星星，「不登入會不見」最有說服力
- **小屋**：原本就有的登入卡（鎖頭圖那張）
- **家長中心**：同意開關上方

原則：至少完成 1 課才提（沒東西可失去就別吵）、可關閉、關掉隔 7 天才再出現。

⚠️ **量測不到轉換率**：引導的曝光與點擊沒有記錄，因為那時候還沒同意，
`track()` 寫不進去。要知道成效只能看 GA4（那是另一套，不受研究同意管）。
